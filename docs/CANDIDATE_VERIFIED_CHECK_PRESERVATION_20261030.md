# 候选贡献：保留已验证区分能力的依赖测试修复

状态：研究候选，不是已证明的新颖机制或效果。2026-10-30。本轮查阅近邻论文并核对现有修复检查代码及保存产物；未实现生产机制、修改RQ/研究计划或追加API。

## 要解决的窄问题

一个测试运行失败，不等于它的全部检查都错误。修复必须允许纠正失败预期，同时防止丢掉原先有效的检查。现有check_repair_integrity主要比较测试名/断言数量并拦截明显旁路；相同断言数量仍可能把精确检查改成弱检查，错误预期的正确替换又可能减少断言数量而被拒绝。

候选命题：在编译成功但运行失败的高依赖Java测试中，能否从修复前已经通过且与依赖行为有关的检查，构造可执行的区分见证，并在允许纠正其他错误预期的同时，保持这些特定见证的检测能力？

“已验证”只指在固定参考版本、固定输入及重复执行中观察到通过和区分作用，不表示规格正确或真实缺陷一定可检测。该方向是回归检查能力保护，不宣称解决一般oracle问题或形式化证明测试意图。

## 拟议机制

1. 对编译成功、可重复执行的失败测试，定位失败检查、此前实际执行通过的检查及独立通过的测试方法；未执行的检查不推断为有效，编译失败不套用本机制。
2. 为依赖相关的有效检查构造有界行为扰动，例如已有stub返回变化、可支持fake中的异常/调用副作用变化；也可对直接相关代码使用局部变异。先冻结扰动与原检查的对应关系，再请求修复。
3. 一个扰动只有在原配置稳定通过该检查、扰动配置确实由该检查失败而区分时，才成为见证。编译错误、超时、无关异常及变化没有传递到目标检查，均不能作为成功见证。
4. 修复候选须通过参考配置，并保留已冻结见证对对应行为的区分作用；不能靠其他新断言杀死不同变异来抵消旧检查失效。未知映射、不稳定扰动或无法支持的依赖回退人工复核，报告可处理比例，不一律接受/排除。
5. 原失败预期不被当作必须保留的真理。是否允许修改仍需源码/规格依据，不能仅复制actual。通过性与见证保持也不证明新预期语义正确，仍保留oracle复核边界。

最小原型先支持简单JUnit4直线测试、可定位的基础断言和已有stub/fake；不先做任意对象状态序列化、复杂异步协议或完整语义等价证明。初步每项检查只选少量已验证见证，记录全部编译/执行/模型成本。

## 解释用例（合成，不代表已观测频率）

原测试检查收据status为SENT（参考版本实际通过），随后错误地断言count为3（参考值为2）。修复将count改成2可能合理，但同时把status检查改为非空则丢失检查力度；两项断言仍在，结构计数不会发现。

在一个明确把依赖返回状态转交给收据的合成程序中，把依赖状态由SENT改为FAILED：原status精确检查应失败，削弱为非空后可能通过。该扰动提供“这项已存在的区分作用丢失”的具体证据，而不只是LLM判断代码像不像。扰动是诊断手段，不宣称FAILED必然是实现缺陷；若真实方法会合法屏蔽该变化，就不能把它强行选为见证。

## 已有本地证据及限制

- 合成AST例子验证：assertEquals("SENT", r.status())变成assertNotNull(r.status())，另一项3改2，现有检查返回ok=true、1个测试方法前后不变；这只证明程序边界，不证明真实问题常见或候选有效。
- 已保存Full CSV修复对中，模型把“调用printComment("x")应抛NoSuchElementException”的try/fail/catch换成精确输出断言；结构检查因断言/异常检查数下降而拒绝。它是可能过度限制的真实线索，需依据冻结源码/规格复核，不能未经核验宣布修复正确。
- A2/A3的JDom修复改变异常预期/输入fixture，说明“全部断言都不许改”不合适。当前仍待语义复核，不把它们算作已经正确的修复。
- 还没有统计足量真实“通过但削弱”的修复对；已有完整性拒绝也不等于检出了语义退化。第一项工作应是去重后的真实频度/可处理性审计，不能跳过准入诊断。

| [MockBench](https://arxiv.org/html/2610.14629v1) | 衡量mock对象、stub、交互断言的可执行性、行为忠实度和交互故障检测 | 问题本身已被识别；候选应提出并验证修复时的保护算法，不能只换benchmark/重复报告“通过不等于忠实” |
| [公开test-weakening benchmark](https://github.com/pooriaarab/benchmark-test-weakening) | 原检查重放、隐藏行为及mutation shield评估 | 不能声称首次用变异检测削弱；需核对其与原测试失败时的部分有效检查保护是否实质重叠 |

上述区别是研究假设，不是已完成排他性新颖性证明。本轮阅读论文及部分仓库说明，没有完整执行或审计全部实现；搜索无精确命中也不是不存在先例的证据。

## 必须比较的简单办法与停止条件

先比较现有结构检查、只修改失败断言/冻结原已通过检查的简单规则、候选见证保持；还需考虑普通变异分数或kill-set保持作强近邻对照，不能挑容易胜出的弱基线。所有方案复用相同保存候选或等额生成预算，验证阶段全部执行成本计入。

核心指标是退化修复漏检、正确修复误拒、支持比例、保留的独立故障检测能力和额外成本；覆盖率与JUnit通过率作补充。用于构造见证的扰动与最终评估故障/变异应分开，不能用同一批见证既约束又宣布泛化效果。真实问题频度与人工标签依据另行报告；单人审查须披露限制。

若真实退化修复很少、失败测试中可建立的有效检查极少，或者冻结已通过检查/局部修复就能取得相同保护，本候选停止，不叠加复杂机制。若先例已有同等机制，也应收缩，不改名称硬保创新。

## 对现行路线的影响

保留KCF的依赖分析、检索、约束、执行与覆盖设施。新机制针对修复准入，不能偷偷并入StaticGuard后用旧A3证明其贡献。若准备生产化，需要先提出能够单独归因的最小对照修订，并获得研究路线确认；当前不新增RQ、替换A1/A2/A3或承诺原消融已足够验证它。
