# 跨阶段请求预算与成本索引

2026-10-30。本模块是正式实验的安全/复现基础设施，不是新的研究贡献，不改变RQ1/RQ2或A1/A2/A3。默认不启用，不修改已配置的云端私有文件，也不因此授权任何新请求。

## 执行语义

`LLMClient`可选读取顶层`request_budget`，见`config/request_budget.example.yaml`。未提供该节时，既有调用行为保持；提供后必须显式设置`llm.max_retries=0`、`KCF_LLM_TRACE_PATH`及每次调用的`trace_target(method_id)`。初始生成、失败修复、覆盖反馈和独立RAG已使用同一客户端边界，因此不依赖每个提示调用点分别实现计费约束。

同一方法在同一变体/重复中的所有阶段使用**同一个绝对ledger_path和同一策略**。另一个变体/重复使用自己的新账本，不能为每个阶段换账本绕开总额；也不能清空账本或换target_id来继续同一额度。账本策略包含模型、固定tokenizer哈希、封装余量和限额，重开时不允许静默改限额。账本能跨进程复用，但正式调度器仍须检查各阶段确实引用相同路径，此点尚未由一个全流程调度器自动保障。

每个请求在实际调用SDK之前：

1. 用本地、哈希固定的tokenizer计数system/user文本，预留固定封装余量；不下载模型或执行第三方tokenizer代码。
2. 限制实际max_tokens不超过策略的输出上限，即使GenerationAgent等调用点显式传8192。追踪同时保存请求原上限与实际有效上限。
3. SQLite事务检查该方法的调用数、累计token额度及单次输入/输出上限，按“输入估计+余量+最大输出”预留最坏额度。同方法只允许一笔未结算请求，不允许并发绕过额度。
4. API返回后用真实prompt/completion usage结算，释放未使用预留；空回复仍收费计入。异常、缺失usage、进程在响应前退出保留预留并阻断该方法后续请求，不能把未知费用当0或自动重发。

`max_total_tokens_per_target`计prompt_tokens+completion_tokens；缓存命中仍是输入token，不因价格较低而从token预算里扣掉。它不是货币金额上限，也不是CPU/GPU墙钟时间。API调用可能在响应前已由服务计费，未知费用必须人工核对后另行审计；当前没有自动释放“错误请求”的机制。

离线计数仍是估计，不保证任何服务模型的精确tokenization。实际输入、输出或合计超过策略/预留会记`overrun`并阻断未来请求，已经发送的这一次无法撤销，报告必须披露偏离。该设施提供实际调用数的预发送上限和保守token预留，不能声称不可超出的服务端精确计费硬上限。

## 可追溯状态

追踪新增`provider_call_attempted`、`budget`、`budget_settlement`，预算拒绝记`budget_blocked`。拒绝是本地事件，不是新增API调用；SDK调用尝试也不保证服务端一定接受/收费。各runner原有completed/success语义仍不同，不能直接拿初始RAG非空输出和KCF编译成功做公平质量比较。

`scripts/summarize_request_costs.py`按target/stage索引全部trace，拒绝重复call_id，分别统计调用尝试、预算阻断、错误、已知usage、未知费用及SDK重试配置。不回填缺失费用，不将API elapsed当作检索/编译/JaCoCo总耗时。旧追踪没有provider_call_attempted时，从旧状态推断并明确记录legacy数量；存在SDK自动重试时不把一条trace冒充一次底层请求。

## 配置和运行边界

样例的12次/240000 token等值只是演示，不是已批准的正式比较预算。正式选择预算仍需配对协议、成本依据和重复数；EvoSuite按35个项目类生成/41方法评估的预算单位也未因此自动统一。不能为了RAG达到同调用数而擅自更换其单次基线定义。

示例合并到新配置后，需要该配置所有阶段都启用本节；既有云端config/private不自动写入。私有配置依旧不提交GitHub，公开元数据继续脱敏。数据库仅保存调用ID、目标、阶段、预留/实际计数和策略，不保存密钥或原文提示。

测试包括跨客户端/阶段累计、重开账本、并发预留、缺失target、策略变更、单次超限、总token预留耗尽、未知usage、输出上限覆盖、空回复收费和供应商错误不自动重试。真实tokenizer的云端smoke使用假SDK且禁止socket，不能说已经完成真实付费运行的预算验证。
