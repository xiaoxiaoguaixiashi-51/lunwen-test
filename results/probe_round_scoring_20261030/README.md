## 已接通的流程

新KCF反馈入口自动要求exact-exec-union，配合passing-only、冻结reference根目录和原始seed execution roots。第0轮从认可种子追溯真实exec并集；每轮新增的可采纳通过套件进入有明确原始路径及exec/JUnit哈希的索引；后续轮按这些原始数据重新生成固定main classes报告。轮间detail直接来自这个报告，缺口选择和下一轮是否还有目标不再依赖XML逐行最大值近似。

旧 `run_stage_b_ours_full_feedback.py` 默认仍是历史XML模式，供历史材料复查；使用新 `run_kcf_utg_feedback.py` 缺少精确模式所需参数会拒绝运行，不会静默降级。运行元数据记录coverage_aggregation。修复后待语义复核的通过测试仍被排除，失败测试不贡献主覆盖。

每轮保存独立accepted_xml_index_snapshot.json及SHA，后续追加索引不会改写先前输入快照；评分中索引/exec/XML/JUnit变化会拒绝输出可信结果。发现不同类版本、来源不唯一且无明确可核验路径、零测试/失败JUnit、参考类树或工具不匹配均拒绝。明确execution_xml必须位于允许的原始执行根目录，其哈希与批准索引一致，不凭路径先后选择“看起来最好”的报告。
