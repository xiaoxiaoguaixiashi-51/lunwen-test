四次模型请求均有回复，全部修复保留了结构性检查要求的测试和检查数量；结构检查本身不证明测试逻辑或断言语义正确。

JDom 完整差异只改变接口实例化用例：`getConstructor()` 先于 `newInstance()` 执行；接口没有 public 无参构造器，触发 NoSuchMethodException，并由源码包装为 IllegalArgumentException。修复保留原 fail() 和 cause 断言，纠正异常类型，并增加消息断言。源码 SHA、78–96 行依据、修复代码 SHA 和复核理由见 `semantic_reviews.json`。该复核由 Codex 做源码/diff 检查，不是独立人工 oracle 认证。

最终六目标有 3 个可采纳的通过套件（原 CLI/Collections + JDom 修复），不是全部失败都已解决。固定 136 行/90 分支分母：采纳套件覆盖为 39/136 行（28.7%）、14/90 分支（15.6%）；之前初始通过套件为 25/136 行、12/90 分支。该工程前后记录不能证明新增机制的因果优势，更不能替代完整覆盖反馈后的正式比较。

## 已完成的工程修复

1. 按执行状态把初始运行失败/编译失败送入现有失败检索与修复，而不是仅按覆盖百分比挑目标。dry-run 精确选出原四个失败套件，且不构造模型客户端。
2. 修复提示补充冻结源码和直接依赖的真实类/接口、构造/方法声明，并记录哈希。它是有界项目上下文，不是新知识筛选、完整图推理或可追溯知识错误归因。
3. 生成修复先验证测试未删除、断言/异常检查未减少、未加禁用/假设/常量布尔断言等；通过后独立编译/JUnit/JaCoCo，运行通过仍须显式语义复核，不能自动纳入计分。
4. 复核采纳创建新的 approved XML 根与闭合哈希索引，不覆写原 accepted/review/失败资料。未来 `--passing-only` 反馈拒绝待复核或哈希变化的种子，仅合并通过套件；失败或未复核的增量修复 XML 不自动合并。
5. 新反馈模式隔离各次 classes、日志和 exec，并显式关闭 JaCoCo append，避免失败执行污染通过执行覆盖。默认旧路线行为保留仅供历史追溯。

A1/A2/A3 的既有定义未替换：本入口的 A1 关闭失败检索，A2 此阶段同 Full，A3 关闭额外项目约束提示/依赖声明；所有版本共同遵守评估完整性门。尚未宣称两阶段正式消融实跑完成。
