## 失败归因

- Parser/F0：生成的 `FakeOption.setOptionalArg` 缩小了父类public方法的可见性。这不是缺少目标完整源码的证据，依赖类Option仍未完整提供。
- Parser/F1：缺少Properties导入、未实现Parser抽象方法flatten、setOptions可见性过低，以及调用不匹配的Option构造签名。F1省略非目标方法签名，确实不足以提供完整的继承/构造契约；但不能将全部错误归因于压缩。
- Parser/F2：仍未实现flatten，并生成不存在的 `Option.setValues`，另有导入/可见性错误。同类被调用方法不等于生成可实例化子类所需的方法签名，也不等于外部Option API。
- Element/F1：一项错误断言认为结果不应含NO_NAMESPACE；另一项在 `Namespace.getNamespace("xml", "http://fake-xml")` 处抛出IllegalNameException，尚未到达该测试的目标调用。这是外部工厂的保留前缀限制，不是此次已经建立了跨对象作用域机制的优势，也不是检索知识条目错误的证据。
- Element/F2：生成多处不存在的 `Element.addNamespace`；实际应核对项目API。增加同类直接调用候选没有防止这类API臆造。

以上以原始Java、compile.log、独立JUnit Result及失败栈交叉核对；不靠模型事后解释。旧A3问题和当前正式Full的问题频度仍须分别统计。
