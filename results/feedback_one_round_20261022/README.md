## 复核与计分保护

直接通过的 CSV 测试已检查，无 Ignore/Disabled/Assume/直接 return/常量布尔断言，11 个测试包含输出内容、换行与注释标记检查。这个检查不等价于证明所有 oracle 正确。

Collections 的完整修复 diff 仅移除未使用的 assertSame import，并把 testTransformIdentity 中 `assertSame(o.toString(), t.transform(o))` 改成 assertEquals。冻结源码中 transform 返回反射调用结果，契约不保证其与另一次 toString 结果引用相同。值相等检查保留了预期行为验证；十个测试未删除。源码 SHA、115–141 行、修复代码 SHA 与理由见 `semantic_reviews.json`。这是 Codex 源码/diff 审计，不是独立人工 oracle 研究。

失败 XML 和未经复核的修复 XML 没有进入自动计分集合；每次尝试的 classes/log/exec 分开，JaCoCo append=false。原 `coverage_round1`、状态文件及自动待复核标记不覆写；复核后结果另存 `reviewed_xml`、`reviewed_evaluation`。

运行后审计工具再次检查了采纳条件、源码/报告哈希和执行目录隔离。随后为未来运行补充了“首次生成执行前也检查已知绕过模式”的入口：本次并未使用这项后补前置检查，不能伪称使用了新版本；本次直接采纳的 CSV 套件已通过同样规则的事后审计。
