源码组在 s1、s2 采用不同前缀，分别检查两个绑定共存。两项实际验证合法共存，原冲突优先级场景无法通过该公共构造路径进入目标方法。规则组在这两项仍构造了同前缀异 URI 的对象，异常栈位于目标调用前。两组 s3 均检查标准 XML 命名空间的存在，s4、s5 均通过。两组 s6 均调用目标方法后错误地断言有三个命名空间，实际为两个。两组均没有整套通过，覆盖按既定规则未准入。

显式规则提示在本次开发对照中未带来额外收益。结合前两轮结果，暂缓将单纯增加规则提示作为论文贡献。两组都出现了对场景或断言的偏差，后续若探索新机制，应分别验证合法构造和目标行为断言，并用未参与调参的目标对照。这个单方法单次结果不足以判断普遍效果。
