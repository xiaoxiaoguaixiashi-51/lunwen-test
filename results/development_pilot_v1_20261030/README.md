## 两个现场发现及修正

1. A1 CSV生成提示超过12000输入上限，在SDK发送前被拒绝，未收费。调度器原先把没有Java文件误当基础设施错误，停止后保留原件。续跑沿用同一账本/配置，从已保存A1初始产物继续；CSV保留初始生成失败、固定分母计零，不重发该生成请求。后续覆盖反馈是原协议允许的新阶段，不是重试被拒绝请求。Full和RAG不重跑；A2/A3随后正常执行。预算未提升，66次总界未绕开。
2. 原EvoSuite CSV进程退出0但控制台无JUnit最终计数，原计分因此排除该套件。不能猜测通过；现统一使用JUnitCore返回的Result独立写文件，保留junit.process.log原输出和失败栈。三执行器均使用这一规则，关闭System.out的真实Java回归通过。对六组保存源码统一重评后，CSV 37测试确实通过；EvoSuite覆盖由10行/2分支修正为12行/5分支，其余组不变。原pilot_summary.json、evidence_audit.json和原归档保留为初始结果，不作为最终表格入口。
