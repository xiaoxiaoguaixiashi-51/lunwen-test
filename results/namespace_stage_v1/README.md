# 对象构造与目标断言分阶段诊断

用 Java 8 在冻结的 JDom 编译类上执行 `scripts/java/NamespaceStageProbe.java`。探针先构造对象，构造成功后调用 `Element.getNamespacesInScope`，最后检查断言。预先给定的八个预期状态均与实际结果一致，API 调用为 0。

| 案例 | 结果 |
|---|---|
| 同元素的额外声明冲突、声明与属性冲突、保留 XML 前缀重绑 | 3 项均在目标调用前被库拒绝 |
| 不同前缀的声明共存、属性共存、子元素遮蔽父元素 | 3 项均调用目标方法并通过断言 |
| 无命名空间的根元素，沿用旧的数量断言 | 成功调用目标方法，断言失败 |
| 同一根元素，使用源码推导的断言 | 成功调用目标方法并通过断言 |

根元素的预期在运行前从冻结源码推导。映射按前缀去重，元素已提供空前缀，因而不会再补一个空前缀条目。结果应含自身的 `NO_NAMESPACE` 和标准 `XML_NAMESPACE`，共两项。合法共存与跨元素遮蔽分别记录为独立的测试意图。

这是手写的阶段诊断原型，验证了对构造失败和断言失败的区分。下一阶段应冻结未参与调参的目标，再比较现有流程和带构造验证的流程，记录意图保留、运行效果及成本。当前证据来自同一个开发目标。
