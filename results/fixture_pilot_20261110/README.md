# Element 对象构造规则小样本对比

此前 F3 的 8 项失败中，4 项发生在目标调用前，涉及同一元素上的命名空间冲突和保留 `xml` 前缀。其余 4 项为断言失败。归因依据是生成源码及对应的 JUnit 栈位置。

云端运行版本 `dba7dd7`。两组使用同一份已存档的 F3 分析、测试计划和签名上下文，各调用模型一次生成新测试。源码组追加固定源码片段，规则组追加人工整理的同元素约束及保留前缀约束。源码片段通过符号常量表达保留 URI，规则组给出 URI 字面量，且明确了跨祖先的作用域，因此这次比较同时改变了信息的表述和明确程度。

| 组别 | 编译 | 测试数 | 构造异常 | 断言失败 | 通过 |
|---|---|---:|---:|---:|---:|
| 源码片段 | 通过 | 18 | 3 | 4 | 11 |
| 显式规则 | 通过 | 18 | 0 | 6 | 12 |

规则组使用了合法的 XML 命名空间，并将两处同元素冲突改成不同前缀，但仍保留了断言另一个 URI 不应出现的预期。这两项从构造异常变为断言失败。两组整套测试均失败，按准入规则未计入覆盖率。两次请求合计 27,906 token，预算拦截 0 次。

这个开发样本支持继续核查构造规则。下一次对照应给源码组完整的等价事实，并检查修改后是否保留可达的测试意图，再考虑未参与调参的样本。当前结果不足以确定论文创新点。
